# voice2dir

**Наговори дерево каталогов — получи его на диске.**

```
голос ──▶ whisper ──▶ транскрипт ──▶ DSL-парсер ──▶ JSON ──▶ дерево ──▶ read-back
         (ASR)        (текст)         (детерминир.)  (схема   (на диске)  (проверка)
                                                     json2dir)
```

`voice2dir` — ещё одно воплощение конверсионной схемы [json2dir]
(https://github.com/alurm/json2dir) / [RFC J2D-1], у которого самый
человеческий вход из возможных: голос. Наговариваешь дерево командами
на русском — оно материализуется на диске и проверяется обратным
чтением (семантика [dir2json](https://github.com/71g3pf4c3/dir2json)).

Вход: `.ogg`, `.mp3`, `.wav`, `.flac`, `.m4a`, `.opus` — любой формат,
который декодирует ffmpeg, — или живая запись с микрофона.
Выход: дерево каталогов, файлов, символических ссылок и исполняемых
файлов; либо JSON в схеме json2dir.

## Быстрый старт

```bash
git clone https://github.com/71g3pf4c3/voice2dir
cd voice2dir
nix develop          # python3 + ffmpeg + whisper-cli + espeak-ng

# из аудиофайла (первый запуск сам скачает модель ~180 МБ):
voice2dir audio заметка.ogg ./дерево

# или наговорить в микрофон (Ctrl+C — стоп):
voice2dir record ./дерево
```

Результат — каталог `дерево`, собранный из сказанного, плюс отчёт об
обратной проверке:

```
voice2dir: дерево записано в ./дерево и проверено обратным чтением
```

Без nix: нужны `python3 ≥ 3.10`, `ffmpeg` и `whisper-cli`
(whisper.cpp) в `PATH`, затем `pip install -e .`.

## Установка

### Nix (рекомендуется)

```bash
nix profile install github:71g3pf4c3/voice2dir
```

Обёртка сама приносит `ffmpeg` и `whisper-cli` в `PATH` — ничего
доводить напильником не надо. Для разработки:

```bash
nix develop    # шелл со всеми инструментами
nix build      # собрать пакет
nix flake check
```

### Из исходников

```bash
pip install .            # python >= 3.10
# и отдельно: ffmpeg, whisper-cli (из nixpkgs: nix shell nixpkgs#whisper-cpp nixpkgs#ffmpeg)
```

Python-зависимостей у пакета **ноль**: ASR и аудио-движки вызываются
как внешние инструменты (`whisper-cli`, `ffmpeg`).

## DSL: как наговаривать дерево

Одна команда — одна произнесённая фраза. Между фразами — пауза.
Ключевые слова нечувствительны к регистру; имена и содержимое
передаются дословно.

| Что говоришь | Что получится |
|---|---|
| `каталог имя` | создать каталог и войти в него |
| `файл имя` | начать обычный файл; дальше — его содержимое построчно |
| `скрипт имя` | начать исполняемый файл (аналог `["script", ...]`) |
| `ссылка имя на цель` | символическая ссылка (аналог `["link", ...]`) |
| `вверх` или `конец каталога` | выйти из текущего каталога |
| `конец файла` | закрыть блок содержимого |
| `конец дерева` | конец диктовки (остальное игнорируется) |

Пример — наговариваешь:

```
каталог демонстрация
файл приветствие
привет мир
конец файла
скрипт проверка
эхо привет
конец файла
ссылка алиас на приветствие
конец дерева
```

получаешь на диске:

```
дерево/
├── алиас -> приветствие
├── демонстрация/
├── проверка*        (#!/эхо привет, +x)
└── приветствие      ("привет мир\n")
```

а в JSON (схема json2dir, `voice2dir build --json ...`):

```json
{
  "демонстрация": {},
  "приветствие": "привет мир\n",
  "проверка": ["script", "эхо привет\n"],
  "алиас": ["link", "приветствие"]
}
```

Правила, которые парсер применяет жёстко:

- **имя — одно слово** (без пробелов): пробел в имени почти всегда
  значит, что распознавание склеило две команды в одну строку — это
  ошибка, а не дерево;
- имя не содержит `/`, не `.` и не `..` (наследие RFC J2D-1:
  относительность путей);
- незакрытый `файл`/`скрипт` (нет `конец файла`) — ошибка с номером
  строки;
- каждая строка содержимого становится строкой файла, в конце —
  перевод строки; пустое содержимое — пустой файл.

## Команды

### `voice2dir transcribe` — только распознавание

```bash
voice2dir transcribe запись.ogg > transcript.txt
```

Печатает транскрипт в stdout. Используйте как первый шаг
двухшагового workflow (см. ниже), чтобы проверить и поправить
расшифровку до материализации.

### `voice2dir audio` — аудиофайл сразу в дерево

```bash
voice2dir audio заметка.ogg ./дерево
voice2dir audio --json голос.mp3              # JSON, ничего не пишет на диск
voice2dir audio --dry-run голос.mp3 ./дерево  # показать, что будет создано
voice2dir audio --lenient голос.mp3 ./дерево  # пропускать нераспознанные строки
voice2dir audio --model ggml-medium-q5_1.bin голос.ogg ./дерево
```

Транскрипт печатается в stderr — видно, что услышала модель, ещё до
разбора.

### `voice2dir record` — с микрофона в дерево

```bash
voice2dir record ./дерево
```

Пишет с источника по умолчанию (PulseAudio → ALSA fallback), **Ctrl+C**
останавливает запись и запускает конвейер. Диктуйте в том же DSL.

### `voice2dir build` — из текстового транскрипта, без ASR

```bash
voice2dir build transcript.txt ./дерево
voice2dir build - ./дерево          # транскрипт из stdin
cat transcript.txt | voice2dir build - ./дерево
```

Детерминированный путь: тот же транскрипт — всегда то же дерево.
Именно сюда стоит прийти после ревизии распознанного текста.

Общие опции: `--json`, `--dry-run`, `--lenient`, `--no-verify`.

## Рекомендуемый workflow: два шага вместо одного

Голос — шумный канал; ASR может ослышаться, склеить фразы или
просклонять имя. Честная дисциплина такая же, как у любой
configuration management: **сначала посмотреть, потом применить**.

```bash
# шаг 1: расшифровать и УВИДЕТЬ
voice2dir transcribe запись.ogg > tree.txt
$EDITOR tree.txt          # поправить: «демонстрации» → «демонстрация»,
                          # убрать склейки, добить имена

# шаг 2: применить проверенное
voice2dir build tree.txt ./дерево
```

Одношаговые `audio`/`record` — для быстрой черновой диктовки; при любой
ошибке разбора они честно падают (exit 1) и **не** строят дерево из
мусора. После правки транскрипта шаг 2 всегда детерминирован.

## Модели распознавания

Модели [whisper.cpp] скачиваются с Hugging Face при первом
использовании в `~/.cache/voice2dir/models/`.

| Модель | Размер | Комментарий |
|---|---|---|
| `ggml-tiny-q5_1.bin` | ~32 МБ | черновики, «на бумажке» |
| `ggml-base-q5_1.bin` | ~57 МБ | короткие фразы |
| `ggml-small-q5_1.bin` | ~181 МБ | **по умолчанию**, рабочий баланс |
| `ggml-medium-q5_1.bin` | ~513 МБ | максимум качества на CPU |

```bash
voice2dir audio --model ggml-medium-q5_1.bin ...
```

Переменные окружения:

- `VOICE2DIR_MODEL` — модель по умолчанию;
- `VOICE2DIR_MODELS_DIR` — куда класть модели (например, общий кэш).

Декодер всегда получает initial prompt со словарём DSL — bias-decoding
заметно улучшает распознавание ключевых слов («конец файла» вместо
«канец яйма»).

## Запись с микрофона

```bash
voice2dir record ./дерево
```

- источник: `pulse` (по умолчанию), при неудаче — `alsa`;
- **Ctrl+C** — стоп: ffmpeg корректно финализирует файл, обрезки не
  будет;
- запись пишется во временный WAV (16 кГц, mono) и сразу уходит в
  конвейер;
- минимальная тишина (пустая запись) — ошибка, а не пустое дерево.

## Верификация и коды выхода

После материализации дерево читается обратно (семантика dir2json:
сортировка, символические ссылки не разыменовываются) и сверяется с
намерением. Расхождение — не «предупреждение», а результат работы.

| Код | Смысл |
|---|---|
| `0` | дерево записано **и** проверено обратным чтением |
| `1` | ошибка: ASR, DSL, I/O |
| `2` | ошибка командной строки |
| `3` | дрейф: обратная проверка не сошлась |

Это тот же канон кодов, что у `dir2json --check` — CI различает
«плохое дерево», «плохая команда» и «канал услышал не то».

`--no-verify` отключает проверку (не рекомендуется).

## Советы по диктовке

1. **Одна команда — одна фраза.** Делайте заметную паузу между
   командами: границы фраз для ASR — это границы строк транскрипта.
2. **Имена — одним словом.** `файл конфиг` — хорошо; `файл основной
   конфиг` — ошибка разбора (и правильно).
3. **Говорите имена знакомыми словами.** ASR увереннее с частотной
   лексикой: `тест`, `конфиг`, `привет` распознаются надёжнее, чем
   редкие термины.
4. **Латиница озвучивается по-русски и пишется кириллицей**
   (`джейсон` → «джейсон»). Если нужно латинское имя — самый надёжный
   путь: `transcribe` → поправить имя в тексте → `build`.
5. **Содержимое — простыми предложениями.** Каждая произнесённая фраза
   станет строкой файла.
6. **После сомнительной диктовки** смотрите транскрипт в stderr (команды
   `audio`/`record` печатают его целиком) — это read-back канала до
   всякого разбора.

## Честные ограничения

- **ASR — вероятностный канал.** Whisper может склеить соседние фразы
  в одну строку, просклонять имя («демонстрация» → «демонстрации») или
  исказить редкое слово. Парсер защищается жёсткой грамматикой (имя
  одним словом, строгие ключевые слова, `конец файла` обязателен) —
  мусорное дерево не построится, будет ошибка. Лечение — workflow
  `transcribe → правка → build`.
- **Регистр и латиница** не контролируются голосом надёжно. Для
  точных имён (`README`, `Makefile`) правьте транскрипт.
- **Синтетическая речь** (TTS-генераторы, робо-голоса) распознаётся
  существенно хуже живого человеческого голоса — whisper обучен на
  людях.
- **Кириллица по умолчанию.** DSL рассчитан на русский (`--lang ru`);
  англоязычный DSL не реализован (patches welcome).
- **Содержимое — только текст.** Как и во всей схеме json2dir,
  бинарное содержимое (не-UTF-8) невыговаримо и не представимо.

## Экосистема

Выход `--json` полностью совместим со схемой [json2dir] (RFC J2D-1):

```bash
voice2dir audio --json голос.ogg | json2dir        # гибридный roundtrip
voice2dir build --json tree.txt | dir2json --check - ./дерево
```

- [json2dir](https://github.com/alurm/json2dir) — нисхождение (Rust,
  оригинал);
- [dir2json](https://github.com/71g3pf4c3/dir2json) — анамнесис и
  drift-check;
- [awesome-json2dir](https://github.com/kitsunoff/awesome-json2dir) —
  канонический список воплощений (voice2dir — голосовая ступень).

## Разработка

```bash
nix develop
python3 -m unittest discover -s tests   # 36 тестов: DSL, материализация, CLI
```

Структура:

```
voice2dir/
├── dsl.py          # транскрипт -> JSON: детерминированный парсер
├── materialize.py  # JSON -> дерево + read-back + diff (схема J2D-1)
├── asr.py          # whisper-cli, ffmpeg-конвертация, модели
├── record.py       # запись с микрофона (pulse/alsa)
└── cli.py          # argparse, коды выхода 0/1/2/3
```

Безопасность схемы — как в RFC J2D-1: имена без `/`, `.` и `..`,
перезапись через удаление, корень — объект. Тесты покрывают грамматику
DSL (включая враждебные случаи: склейки, `..`, вложенные ключевые слова
в содержимом) и полный roundtrip материализации.
